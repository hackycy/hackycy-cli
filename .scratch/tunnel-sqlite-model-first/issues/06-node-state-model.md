# 决定 Node 身份与运行状态的模型

Type: grilling
Status: resolved
Parent: ../map.md
Blocked by: 02, 04

## Question

新 Node 的 SQL schema 与 Ent 模型应如何一致地表达身份、Controller 绑定、最高修订、候选快照、最后成功配置及进程所有权？在固定的新状态子目录内，决定首次初始化、重启恢复、损坏状态拒绝，以及可再生成的 FRPS 运行文件如何清理和恢复，保持现有管理协议行为。

## Answer

- 新 Node 数据库从 v1 开始，由三个 Ent 单行模型承载业务状态：`Identity` 保存 Node ID 和 X25519 私钥/公钥，`ControllerBinding` 保存首次 claim 的 Controller 公钥，`RuntimeState` 保存运行高水位与恢复检查点。SQL 结构资产定义固定单行 ID 和密钥字节长度的结构约束，Ent Schema 与之同步；Identity 和 RuntimeState 在首次初始化时必须各有一行，ControllerBinding 在未认领时没有行。首次 claim 只插入绑定，不覆盖已有 Controller；并发 claim 由单行唯一约束决定先后，保持 `NODE_ALREADY_CLAIMED` 行为。未来 schema 演进遵守独立的 migration 维护约束，本次不实现版本记录。
- RuntimeState 保存最高已接受修订及摘要、候选快照原始字节、阶段、已应用修订、最后成功运行的快照原始字节、`boot_disabled`、`disabled_complete`、失败码和 FRPS 所有权。原始字节是必须保留的协议载荷，不经 ORM JSON 重序列化；摘要针对这些精确字节计算。无需历史快照表。SQL 结构资产定义非负修订、已应用修订不超过最高修订、阶段取值、所有权字段成组有效，以及 `disabled_complete` 必须伴随 `boot_disabled` 且最后成功快照为空等基础 `CHECK`；Ent Schema 与之同步。快照格式、Node ID、修订匹配、SHA-256、X25519 密钥对及其他跨字段恢复语义由 Go 在写入和启动时验证。
- 所有权只保存 PID、平台可提供时的进程创建时间、FRPS 程序路径和配置路径。创建时间为零表示平台无法取得，不能当成损坏；PID 为零时其他所有权字段必须为空。删除只为旧 v3/v4 迁移保留的 `owner_started` 和迁移分支，新 v1 不读取旧 Node 数据库。
- 首次启动只允许在新的 `<data-dir>/node-state-v1/` 不存在或为空时进行。继续使用用户指定 `--data-dir` 的根目录进程锁，在新子目录内先留下私有的初始化标记，再按当前 v1 SQL 结构资产建空库，并在事务中生成及保存身份和初始运行行；初始化中途失败后留下的不完整子目录不能被悄悄当成新节点。旧目录及其中的旧数据库、标记和 FRPS 文件一律不读取或清理。
- 已有新状态必须先只读检查初始化标记、私有常规数据库文件及 WAL/SHM、当前 v1 结构及 SQLite 完整性；含 WAL 的数据库沿用私有副本检查，避免损坏状态检查时改写原文件。验证目标结构、必需单行记录、密钥对、绑定公钥长度和运行状态关系。候选快照若最高修订大于零，必须能解码且其修订和摘要匹配；最后成功快照若存在，必须是与已应用修订相符的有效 running 快照。缺失、损坏或结构不匹配就拒绝启动，不重置身份；明确重置须由操作者移走整个新子目录。正常文件继续保持私有权限及 Windows ACL。
- 接受候选时先完整校验协议快照，再在一个事务中写入最高修订、摘要、原始字节和 `accepted` 阶段；旧修订返回 `NODE_REVISION_STALE`，相同修订不同摘要返回 `NODE_REVISION_CONFLICT`，相同修订相同摘要保持幂等。应用失败不回退已接受的高水位。running 应用在停止旧进程前持久化 `switching`，成功启动并记录所有权后才把候选设为最后成功快照、推进已应用修订；失败时从最后成功快照回滚并记录现有失败码。disabled 应用在停止进程前持久化 `boot_disabled` 和 `disabling`，确认停止后清除最后成功快照并标记完成，防止崩溃后误启动旧配置。
- 重启恢复先清理新子目录中已中断的 `snapshot-*` 传输文件及 `.frps-file-*` 临时文件。只对数据库登记且经 PID、创建时间（可用时）、程序和配置路径核验通过的 FRPS 执行终止；所有权不明时不终止进程、不清理其 FRPS 文件，管理状态报告 `FRPS_OWNERSHIP_UNKNOWN`。未登记进程不接管。禁用意图继续完成已登记进程的停止与文件清理；运行状态从最后成功快照重新生成配置和 404 页面并恢复 FRPS，未完成候选留待 Controller 重试。生成文件只位于新子目录，按需从数据库快照重建；完成禁用且确认停止后删除生成的 `frps-*.toml` 与 `frps-*-404.html` 常规文件。FRPS 启动、验证或回滚的运行故障仍由管理状态报告，不把有效数据库误判为损坏状态。
- 实施验收覆盖空目录初始化、重复启动、当前 v1 结构检查、缺失标记/数据库/运行行及损坏快照拒绝、首次 claim 和重放、修订冲突、运行与禁用的各持久化检查点崩溃恢复、所有权不明与未登记进程、临时文件清理及生成文件重建。旧 v3/v4 自动迁移测试改为旧状态隔离测试；管理协议和状态错误码保持现有行为。
