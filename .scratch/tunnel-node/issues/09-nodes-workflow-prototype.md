# Nodes 页面怎样让认领、分配和故障状态可理解？

Parent: [Tunnel Node 接入设计地图](../map.md)
Type: prototype
Status: resolved
Blocked by: 02, 05, 08

## Question

以粗糙页面流程或可点击原型验证：所有登录用户可见的本地/远端 Node 摘要列表与选择器、普通用户将自己 Client 切换 Node、管理员添加 Node（管理地址/Node 指纹/名称，无配对码）、认领成功及失败反馈、管理地址与对外 FRP 地址的区分、Node 离线/配置失败/待移除/强制遗忘时的提示。必须让 Server 端清楚解释已被其他 Server 认领、指纹不符、不可达等认领失败；普通用户不可见管理地址、指纹和详细错误；不能出现 Node 授权或改绑操作。原型要覆盖一个已在运行的 Client 从本地迁移到远端 Node 的操作路径，并让用户判断文案、信息量与危险操作是否符合预期；反馈后再定正式 UI 行为。

参照：[现有 Web 导航](../../../web/tunnel-server/app.tsx)、[实现交接入口](../spec.md)及[可点击流程草模](../nodes-flow-prototype.html)。

## Comments

### 2026-09-23：草模已制作，待用户体验

交互草模：[Nodes 流程原型](../nodes-flow-prototype.html)。这是独立的、可双击打开的 HTML 文件，不连接当前 Tunnel Server，不保存数据；刷新页面重置。选择逻辑状态原型而非视觉风格变体，因为本票据主要验证认领、切换、故障和移除时的状态与文案，正式视觉样式尚未确定。

草模提供管理员/普通用户视角切换、全部 Node 摘要列表、管理员详情、认领预览/核对/失败、Node 配置失败、Client 在线切换后 FRPC 失败、离线待切换、正常移除和强制遗忘的场景步骤及自由操作。正常移除要等持久停用确认；强制遗忘要二次确认。所有示例指纹、地址、状态均为模拟值。

已执行 JavaScript 语法检查，并用 Node 运行内存状态模型的认领、切换失败不回退、离线待切换、重新连接后提交等关键转换。内置浏览器因 `file://` URL 策略拒绝打开此本地文件，因此未进行浏览器视觉走查；不尝试通过其他浏览器入口绕过该限制。等待用户在本机打开后给出流程与文案反馈，再把最终 UI 决议写入 `## Answer` 并关闭票据。

### 2026-09-23：用户反馈

用户查看草模后表示“暂时没有想要调整的”。据此接受当前草模中的流程、信息层次和操作文案作为首版设计依据；“暂时”不表示最终视觉样式已锁定。草模保持独立于生产页面，实施时根据实际组件和真实接口重做。

## Answer

- 主导航增加所有已登录用户可见的 **Nodes** 入口。列表包含 Local Node 与全部 Remote Node，展示名称、类型、对外 FRP 地址、HTTP 公网入口、可用性、Node 管理连通性和带时间的 FRPS 观察。普通用户可查看公共摘要，并在自己的 Client 页面从全部可用 Node 中选择目标；没有 Node 授权流程。管理员另见管理地址、指纹、期望/已应用版本、详细故障与管理操作。
- **Add Node** 仅管理员可用。表单输入公网 HTTP 管理地址与显示名，先预览 Node 指纹，要求与 Node 本机输出核对后再确认认领；无配对码、本机批准、远程改绑或 reset 操作。认领成功后单独显示“已绑定但尚需配置和启动 FRPS”，不得立即标成可分配目标。已被其他 Server 认领、指纹不符、管理地址不可达、协议不兼容分别显示稳定原因与下一步，不能只给笼统失败文案或泄露原 Controller 身份。
- Node 卡片和详情将**管理连通性、FRPS 运行、配置收敛**分别呈现。Node 离线时上次 FRPS 运行结果标为历史观察，当前运行未知；配置新版本失败但回滚成功时保留已应用版本并说明旧 FRPS 继续运行。不能以“在线/离线”一个状态覆盖所有故障。
- Client 页面把**当前归属 Node、待切换目标、Client 控制连接、Client 已应用 Node、FRPC 到目标 Node 的连接结果**分行显示。在线且目标预检可用时直接提交新归属，后续 FRPC 连接失败不自动回旧 Node；Client 离线时只显示“待切换”，重连且目标可用后才提交。不可用或待移除 Node 在选择器中展示状态但不能作为新的切换目标。普通用户只能操作自己 Client，管理员可处理所有 Client。
- 正常移除仅适用于无当前归属和待切换 Client 的 Remote Node：先显示**待移除**，远端持久停用确认后才从活动列表消失；Node 离线时不宣称已停用。强制遗忘是单独的危险操作，必须再次明确提示“只删除 Server 记录，远端 FRPS 可能继续运行、旧凭据可能仍有效、Node 本机仍绑定原 Controller”。Local Node 没有移除操作。
- 以上页面行为以[可点击流程草模](../nodes-flow-prototype.html)和用户本轮“暂无调整”的反馈为验收依据。草模中的示例地址、指纹和模拟按钮只用于讨论；正式视觉、组件代码和服务接口在实施阶段完成。
